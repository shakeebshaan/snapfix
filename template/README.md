This is a **snapfix** board — a screenshot-to-AI-fix QA tracker for this project. It was generated by [`snapfix`](https://github.com/shakeebshaan/snapfix). GitHub is the only backend: this public repo serves the board and stores issue metadata; a separate **private** repo stores the screenshots.

## What this repo is

| Path | What it holds |
| --- | --- |
| `index.html` | The board — a single static page, served by GitHub Pages. No build step. |
| `config.js` | `window.QA_CONFIG = { owner, repo, privateRepo, branch }` — written by `snapfix init`. If absent, the board auto-detects these from the Pages URL. |
| `data/issues.json` | Every issue's **metadata** (id, route, description, status, fix notes, who filed/fixed it). The board reads and writes this via the GitHub API. |
| `data/loop.json` | The loop's **live goal** — the satisfaction bar (0–100) a fix must clear to post, and the test gate toggle. The board's header slider writes it. |
| `tools/qa.mjs` | A config-driven CLI the fix-issues skill uses to read open issues and post fixes (enforcing the goal gates). |
| `tools/loop.mjs` | The loop runner — manual/schedule/action triggers + the verifiable test gate. Run `node tools/loop.mjs status`. |
| `recapture.mjs` | Playwright script that re-screenshots a route to prove a fix. |
| `qa.config.json` | Project config (repos, dev server, viewport, auth, loop goal). See the snapfix README + LOOP.md. |

**Screenshots are never in this repo.** They live only in the private repo (`REPO-private`), uploaded straight through the GitHub API. This public repo holds metadata and the static board — nothing else.

**This board is multi-user.** Anyone with a fine-grained PAT (Contents R/W on both repos) can file, fix, and review from their own browser — every action is attributed to their GitHub login (you'll see *filed by* / *fixed by* / *answered by* on each card).

## File an issue (from your phone or any browser)

1. Open the **live board** (link above).
2. Tap the connection chip in the header and paste a **fine-grained Personal Access Token** with **Contents: Read and write** on both this repo and the private images repo. The token is stored only in your browser's `localStorage`.
3. Tap **+**, attach a screenshot, type what's wrong (and the route, if known), and submit. The image goes to the private repo; the metadata lands in `data/issues.json`.

## How fixes happen — the loop

The fix is a **loop** (trigger + goal). It's driven by the **fix-issues** Claude Code skill installed in the *app* repo (`.claude/skills/fix-issues/`). In the app project you run the agent, which:

1. reads open issues + the live goal via `tools/qa.mjs pull`,
2. edits the real app code to fix each one (root cause, not cosmetic),
3. meets the **goal**: the app's **tests pass** (verifiable) *and* the agent's **self-score ≥ the satisfaction bar** (LLM-as-judge),
4. recaptures proof with `recapture.mjs`,
5. posts a before/after card back to the board (`tools/qa.mjs resolve`) with the goal proof.

You then verify on the board: **✓ Resolve**, **✗ Not fixed**, or **↩ Respond** to a question the agent flagged.

**Tune the bar:** tap **◎ judge ≥ N** in the header to move the satisfaction slider — higher means the agent refactors more before a fix is allowed to post. **Automate the trigger:** `node tools/loop.mjs schedule` (cron) or `node tools/loop.mjs watch` (kick the agent when a new issue lands).
